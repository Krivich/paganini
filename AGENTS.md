# AGENTS.md

Paganini Ukulele: a static browser game that teaches ukulele/piano/sax by ear via a falling-notes UI and live microphone pitch detection. Vanilla JS ES modules, **no package.json, no build, no tests, no linter**. Published on GitHub Pages at https://krivich.github.io/paganini/ (remote `Krivich/paganini`, branch `master`).

## Run / verify
- Serve over HTTP, never open `index.html` as `file://` — ES modules, `fetch('./songs/...')`, and `getUserMedia` all require an HTTP/secure context. E.g. `python -m http.server 8000` from repo root, then open `http://localhost:8000/`.
- Entrypoint: `index.html` -> `script.js` (`<script type="module">`). No bundling or codegen; files load by relative path.
- Manual check: pick instrument, grant mic, calibrate (play fret 1, then fret 12, until each reaches 3 stable samples), pick a song. Debug values render in `#debugInfo` (`debugDetectedFrequency`, `debugTargetNoteId`, `debugExpectedFrequency`). A live FFT strip is always visible at the bottom of the screen (see `spectrum.js`).
- Deploy = push `master`; GitHub Pages serves this directory as-is, no build step.

## Architecture (non-obvious)
- `script.js` is the orchestrator: mic + `AudioContext`, a one-time background measurement (1.5 s: average **RMS** plus a per-bin linear **spectral profile** and a **mean magnitude spectrum** for spectral subtraction), then per-frame pitch detection via `detectYin` (`pitch-detector.js`). YIN = FFT-accelerated autocorrelation (difference function -> cumulative-mean-normalized difference -> threshold 0.15 -> parabolic interpolation); it is robust to missing fundamentals and small nonlinear speakers, unlike a raw FFT bin peak. Before YIN, `subtractBackground` (`spectral-subtract.js`) over-subtracts the measured stationary background (fan/hum) from each frame (keeping its phase) — without it the projector's ~436 Hz fan line makes YIN lock onto the fan instead of a quiet note. `detectYin` returns `{ frequency, confidence, mode }` (`mode` = `threshold` | `fallback` | `none`). A frame is accepted only when `rms > max(backgroundRms * 1.2, 0.0015)`, `confidence >= 0.35` (or `>= 0.7` when YIN `mode === 'fallback'`), **and** the note's harmonics exceed the background profile (`noteExcessOverBackground >= 2.5`, `NOISE_HARMONICS = 6`) — the last gate rejects a steady fan/hum or a leaf blower even when it sits on a plausible frequency. Per-instrument `minFreq/maxFreq/highpassHz/windowSize` live in `DETECTOR_SETTINGS` (`script.js`).
- `spectral-subtract.js` (`magnitudeSpectrum`, `subtractBackground`) — standalone pure-JS FFT module used by `script.js` (window `SUBTRACT_N = 4096`, over-subtraction `SUBTRACT_ALPHA = 2`, floor 5%). `?nosub` disables it. Correct detections come out as YIN `mode=threshold` (c≈0.9); the residual fan still yields low-confidence `fallback` frames around 110–340 Hz.
- `?detlog=1` streams a per-frame detection log (`f=`, YIN `mode`, `c=` confidence, `E=` excess, `rms`, gates, top-3 FFT peaks): it is batched and POSTed to the dev server (`/__log`, which appends to `<outDir>/<name>.log`, reset on the first batch of a session) and mirrored to the console — it is **not** drawn over the UI (that covered the song dropdown). `?detlogui=1` additionally shows the old top-right panel. `?nosub` disables spectral subtraction.
- `Game` (`game.js`) spawns falling note elements into `#gameArea`; the leading note **freezes** the game at the instrument "deck" (`Instrument.getDeckTop()`), and a correct note triggers `shiftActiveNotes`. Matching uses `instrument.getExpectedFrequency(noteId)` and `instrument.calculateFrequencyDelta(noteId)`. `getTargetFrequency()` returns the expected frequency of the note in the hit window (used by the spectrum strip).
- `spectrum.js` (`SpectrumStrip`) draws a live FFT strip on the `#spectrum` canvas pinned to the bottom of `#controls` (height `--spectrum-h`): log-frequency bars from `freqDb`, the measured `backgroundSpectrum` as an orange curve (so the fan/hum peak is visible), a yellow dashed marker for the current target note, and a green marker for the **accepted** peak (the frame that passed the gate and was forwarded to calibration/game). It is a diagnostic overlay only — it does not affect detection.
- `instrument-factory.js` maps `ukulele|piano|saxophone` -> classes. The `Instrument` base contract is `draw`, `getNotePosition`, `getExpectedFrequency`, `calculateFrequencyDelta`, `getDeckTop`. Add a new instrument by implementing it, registering it in the factory **and** the `<select>` in `index.html`.
- On-neck feedback (ukulele): `getNotePosition` drops a note into the **press gap between fret wires** (fret N = between wire N-1 and N; fret 0 = the nut), not onto the wire. `showTarget(noteId)` draws a green dot + highlights the melody string (`melodyString`, 0 = top) for the note nearest the deck (`Game.getTargetNoteId`); `showHeard(freq)` draws a red band at the press position of `freqToFret(freq)` (chromatic: one fret = one semitone above `calibratedFrequencies[0]`), held ~0.9 s after the last clear pitch. Elements `#ukuleleTarget` / `#ukuleleHeard` (see `style.css`). Note: song data is fret-only (one calibrated string), so `melodyString` is a visual cue, not per-note tab; the player taps the neck to choose which of the 4 drawn strings it is (`onNeckClick`/`setMelodyString`, persisted in `localStorage['ukulele.melodyString']`, default top). When editing `ukulele.js`, bump the version query on its import in `instrument-factory.js` **and** on `instrument-factory.js` in `script.js`, plus `script.js?v=` in `index.html` - the WebView caches modules by URL.
- Calibration is duplicated per instrument: `UkuleleCalibration` (`ukulele-calibration.js`) extends `Calibratable` and is self-contained — states `lowFret1` -> `highFret1` -> `completed`, measures frets 1 and 12, extrapolates frets 0 and 13. Each accepted sample is the **median** of a confidence-gated rolling window (frames with no pitch are ignored, not treated as instability), and 3 samples within ~1% are required, which tolerates fan/rumble far better than the old min/max ±3 Hz window. `Piano` currently uses `NoCalibration`. `calibration.js` exports a legacy `Calibration` class that **nothing imports**; it still references a non-existent `#startButton`.
- `Calibratable` (`calibratable.js`) is a separate interface (not a base of `Calibration`) with `startCalibration/handleAudioInput/isCalibrationComplete/getCalibrationData/resetCalibration`; `script.js` dispatches through `currentInstrument.calibration`.
- Songs: `songs/songlist.json` maps filenames to instruments; each song is `{ title, instruments, data }` where `data` is a flat array of 1-based note IDs (fret for ukulele, key number for piano). Song filenames are Cyrillic — keep them byte-identical and register new songs in `songlist.json`. `Кузнечик.json`, `Деревня-дураков.json` and `Пираты-Карибского-моря.json` are tracked and registered.

## Self-check
- `self-check.js` (started from `script.js`) automates a full playthrough: it drives an `OscillatorNode` to auto-pass calibration and then plays each target note's expected frequency until the song ends (`Finished!`).
- Enable via query params on the served URL: `?selftest=1` (speakers -> mic loopback), `?selftest=virtual` (also injects the tone straight into the analyser — deterministic, works headless/without a mic), `&autostart=1` (skip the click; needs a permissive autoplay policy), `&song=<file>.json` (default: first song for the instrument). State is exposed on `window.__selfCheckRunning/__selfCheckDone/__selfCheckFailed`.
- While `?selftest` is set, `script.js` requests the mic with `echoCancellation/noiseSuppression/autoGainControl` disabled so the routed tone is not cancelled.
- Gotcha: the self-check places its tones on FFT bin centers (a legacy of the removed peak detector); YIN does not need it but it is harmless. Its high tone is `lowTone * 2^(11/12)`, i.e. fret 1 -> fret 12 (11 semitones), so the calibrated fret map matches the on-neck markers. YIN ignores constant/DC offsets, but a strong *tonal* low-frequency rumble can still pull it down, hence the per-instrument `highpassHz` **and** the spectral subtraction above. With subtraction on, the acoustic speaker->mic self-check completes end-to-end on the Android projector (low tone ~328 Hz then ~621 Hz through the air, then the song runs to `Finished!`). In Chrome, feed the fake mic silence (`--use-file-for-fake-audio-capture`) so it does not add its own tone.

## Known gaps / gotchas
- Saxophone is a stub: `saxophone.js` returns a fixed 440 Hz and a rough 1–8 note map. Its `NoCalibration` implements the calibration interface as no-ops, so it loads without throwing.
- Piano is fixed at 44 keys starting at octave 3; there is no calibration-driven keyboard layout in this revision.
- `anzlyzer/` (misspelled) is a standalone pitch-detection debug page (`analyzer-debug.html` + `frequency_analyzer.js`): a scrolling **waterfall spectrogram** (frequency×time) with the game's YIN detector plus FFT/HPS/autocorrelation comparison, a "Capture background" button and an SNR-excess readout. Not part of the game or referenced by it.
- `copy.bat` (root and `anzlyzer/`) concatenates all `.js`/`.html`/`.css` into `combined_output.txt` for pasting into an LLM. `combined_output.txt`, `out.txt` (empty), `project.txt`, `qwen_context.txt` are local AI-context scratch, not app code. There is no `.gitignore`, so these appear untracked.
- `ANDROID_PROJECTOR_NOTES.md` (Russian) documents running the deployed game on an Android projector with a USB mic, including `adb` steps.

## Android kiosk APK (no permission dialog)
- Problem: TV Bro (and plain WebView) show a mic permission dialog on every page load; kids can't read/press it. Fix: a tiny WebView wrapper app ("Paganini", package `xyz.krivich.paganini`) that silently grants the mic.
- Project lives **outside the repo** at `C:\Users\zubov\AppData\Local\Temp\opencode\paganini-kiosk` (`AndroidManifest.xml`, `src/xyz/krivich/paganini/MainActivity.java`, `res/`, `build.ps1`). The APK just loads the web app (default `https://krivich.github.io/paganini/`), so the web app stays the single source of truth.
- `MainActivity` grants in `WebChromeClient.onPermissionRequest` (`request.grant(request.getResources())`), requests OS `RECORD_AUDIO` once, is fullscreen/landscape/keep-screen-on, and reloads the URL in `onNewIntent` (manifest `launchMode=singleTask`).
- Build (offline, no Gradle): `powershell -ExecutionPolicy Bypass -File build.ps1` — uses `javac` (JDK 17) -> `d8` -> `aapt2 compile/link` -> `aapt add classes.dex` -> `zipalign` -> `apksigner` with `C:\Users\zubov\.android\debug.keystore` (SDK build-tools 34.0.0, `platforms/android-34/android.jar`). Output `build\paganini.apk` (~17 KB).
- Install pre-granting the mic: `adb install -r -g build\paganini.apk`. Test against the local dev server: `adb reverse tcp:8137 tcp:8137` then `adb shell "am start -n xyz.krivich.paganini/.MainActivity --es url 'http://localhost:8137/?selftest=virtual&autostart=1'"` (keep the single quotes or the device shell eats `&`).
- **Gotcha:** without `android.permission.MODIFY_AUDIO_SETTINGS` Chromium cannot open the mic (`getUserMedia` -> `NotReadableError: Could not start audio source`, native log `Unable to select communication device!` at `media/audio/android/audio_manager_android.cc:885`). TV Bro declares that permission; the wrapper must too.
- **Android TV visibility:** the activity must declare **both** `android.intent.category.LAUNCHER` and `android.intent.category.LEANBACK_LAUNCHER`, the app a TV `android:banner` (320x180) and `android.hardware.touchscreen` as not required; otherwise the projector's TV launcher installs the app but hides it (it only lists leanback apps). It then shows under "Installed games".
- Diagnostics: JS errors + `window.isSecureContext` are logged to logcat tag `PAGANINI` via the `AndroidBridge.log` JS interface injected by the wrapper. `http://localhost` is a secure context in this WebView, so local testing works.

## Releases
- Web: pushing `master` deploys https://krivich.github.io/paganini/ via GitHub Pages (no build step). Push the web app **before** the APK, since the APK loads the Pages URL.
- Android APK: the kiosk project lives outside the repo (see above). Build the debug-signed APK, bump `--version-code/--version-name` in `build.ps1`, then publish a GitHub Release on `Krivich/paganini` with the APK attached:
  ```
  gh release create vX.Y.Z build\paganini.apk --repo Krivich/paganini --title "Paganini X.Y.Z" --notes-file RELEASE_NOTES.md
  ```
  Stable download link: https://github.com/Krivich/paganini/releases/latest/download/paganini.apk
  (`gh` needs auth: a token is available from the stored git credential, or `gh auth login`.)
